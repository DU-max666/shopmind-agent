# 幻觉治理：四板斧 + 语料工程

电商客服的幻觉集中在**可验证的事实**上：价格、库存、尺寸、时限、订单号、金额。
本项目不做"事后语义打分"式的模糊治理，而是把幻觉收敛为**可机械校验的硬约束**，
四板斧层层递进，任何一层失守都有下一层兜底。

## 板斧一：数字回查（safety/grounded_check.py）

把答案按句切分，**每个句子中的数字串必须出现在证据文本中**：

```python
check("台灯现价 129 元【M-ZP-DG-001】", evidence)
# → GroundingResult(score=1.0, unsupported=[])   # 129 可回查
check("台灯现价 99 元", [])
# → score=0.0, unsupported=[该句]                 # 编造价格直接标红
```

- 数字用 `\d+(\.\d+)?` 全量抽取：中文金额、日期、时效、单号一网打尽；
- 无数字的定性句不惩罚，避免误杀"好的，马上为您查询"这类服务用语；
- 整句无数字幻觉（如编造品牌名）由板斧三的 LLM 复核补位。

## 板斧二：引用溯源（safety/citation.py）

答案中的每个 `【doc_id】` 必须属于本轮证据集；含数字的事实句**必须带引用**。
校验器输出 `(used, unknown, missing, unverified)` 四元组：

- `unknown`：引用了不存在的证据 → 规则层直接判失败转人工；
- `missing`：报数字不给出处 → 判"答非所据"；
- `unverified`：引用存在但句中数字不在该 doc 内 → 记入问题清单。

**为了让引用可回查，知识库语料按约定编写**（`scripts/init_kb.py`，这是本项目
区别于"套壳 RAG"的原创点——语料工程为治理服务）：

| 文档类型 | 约定 | 效果 |
| --- | --- | --- |
| 说明书 | 每个段落自带完整型号（如 `ZP-SF-001 日常售价 1299 元`） | 引用 `【M-ZP-SF-001】` 时单号数字可在同证据集回查 |
| FAQ | 答案尾注条目编号 `（FAQ-004）` | `【FAQ-004】` 引用自洽 |
| 政策 | 按"第X条"切块，条款含具体时限数字 | `【POLICY-RMA】` 与 7/15/30/72 等时限强绑定 |
| 工具证据 | `ORDER-/LOG-/INV-/TK/RH-/PROMO-CALC` 命名空间 doc_id | 工具返回值同样纳入回查域 |

## 板斧三：置信三态（safety/confidence.py）

`decide()` 综合"路由置信 + 证据一致性"输出三态动作：

```
human   证据一致性 < grounded_min(0.8)，或置信 < clarify_threshold(0.55)：不硬答，转人工
clarify 中置信（0.55~0.75）：先向用户追问补槽位
answer  高置信（≥ 0.75）且证据达标：直接作答
```

阈值来自配置（`ROUTE_ANSWER_THRESHOLD` / `ROUTE_CLARIFY_THRESHOLD` / `GROUNDED_MIN_RATIO`），
三态占比本身就是可运营的质量旋钮：调低作答线=更多澄清，调高=更激进的自动回复。

## 板斧四：规则 × LLM 协同校验（safety/rule_llm_validator.py）

- **规则层（零成本、确定性）**：违禁话术（"绝对最低价""保证没问题"）、越权承诺
  （"已退款""已打款"——售后资金动作必须走工单状态机）、板斧一/二的硬约束；
- **LLM 层（语义补位）**：把证据区与答案一起交给模型，要求输出
  `{"consistent": bool, "reason": ...}`，专抓规则层看不见的语义级幻觉；
- 任一层不过 → 丢弃草稿，替换为转人工兜底话术，`needs_human=True` 记入审计。

## 评测口径与结果（eval/run_eval.py）

- 幻觉率 = 全链路轮次中"答案存在不可溯源数字句"的占比 → **0.0%**（22 轮）；
- 引用完整率 = 事实句均带有效 `【doc_id】`（或本就无事实）→ **100.0%**；
- 检索命中@3 → **100.0%**（30 条，命中是幻觉治理的上游前提）。

四板斧的关系一句话总结：**检索给对证据（命中@3），生成只许抄证据（数字回查），
引用必须能回查（doc_id 溯源），回查不过就升级（规则×LLM + 三态）**。
